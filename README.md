# nixos-config

NixOS system configurations managed via flakes. Modular setup with per-host configurations and shared modules.

## Structure

```
hosts/
  north/                  build workstation
modules/
  core.nix                essentials (git, neovim, tmux, gh, ...)
  desktop.nix             GUI (niri, kitty, brave, waybar, ...)
  remote-access.nix       SSH, xRDP
```

## Usage

```
just rebuild              rebuild and switch to new configuration
just boot                 rebuild, activate on next boot
just test                 test config (rollback on next boot)
just update               update flake inputs
just gc                   garbage collect old generations
```

## How it works

Instead of editing `/etc/nixos/` directly, the actual config lives in this repo
under `~/code/nixos-config` so it can be version-controlled and managed as a
regular user. The bootstrap script places a thin flake in `/etc/nixos/` that
simply points to this repo:

```nix
# /etc/nixos/flake.nix (generated by bootstrap.sh)
{
  inputs.config.url = "path:/home/charemma/code/nixos-config";
  outputs = { config, ... }: config;
}
```

All actual configuration stays here, `nixos-rebuild` just follows the redirect.

## Bootstrap

On a fresh NixOS install:

```
git clone git@github.com:charemma/nixos-config.git ~/code/nixos-config
~/code/nixos-config/bootstrap.sh north
```

This clones the repo, writes the redirect flake to `/etc/nixos/`, and runs the
initial rebuild.
